## Compact description

**IQ Mindware is a Trident-G-based adaptive intelligence platform business that uses a current paid training product, a future transfer-testing upgrade path, readiness-state measurement, free feeder tools, CRM activation and proof-led content to test whether transferable cognitive performance can become a scalable, evidence-generating product category.**

The present structure is already clear in the strategy documents:

| Business role              | Current asset                            | Function                                                                                                   |
| -------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Current revenue engine** | Trident G IQ Pro                         | Paid 20-session adaptive intelligence programme and first proof/content anchor                             |
| **Upgrade path**           | IQ Coach                                 | Next-generation transfer-testing platform with problem spaces, prompts, delayed checks and proof dashboard |
| **Readiness bridge**       | Zone Coach                               | State/readiness gate linking cognitive training to Flow Zone                                               |
| **Feeder layer**           | Mission tools and puzzles                | Social discovery, email capture, IQ Coach waitlist growth and proof demonstrations                         |
| **Proof layer**            | G Tracker / proof pages / delayed checks | Claims boundary, user activation evidence, before/after and delayed probes                                 |
| **Operating cockpit**      | Kastel Node: IQ Mindware                 | Weekly Action/Clarify Intent review and script banking                                                     |

That matches the attached operating architecture, where IQ Pro is the revenue product, IQ Coach is the upgrade product, Zone Coach is the readiness bridge, mission tools/puzzles are feeders, the proof layer handles claims and delayed checks, and Kastel is the operating cockpit. 

## Palantir-style, but Trident-G-framed

A Palantir-style description would be something like:

> IQ Mindware is building an operational intelligence layer for cognitive performance training: it maps users, training states, proof signals, content signals, CRM events and partner opportunities into a shared business ontology, then routes weekly decisions through supervised Action and Clarify Intents.

A Trident-G/Kastel version is stronger:

> IQ Mindware is a live scaling-model hypothesis for adaptive intelligence training. Its core task is to discover whether state-gated cognitive training, relational reasoning practice, problem-space transfer, proof telemetry and claim-safe content can form a strategic invariant that survives changes in wrapper, segment, channel and partner context.

So the business is not just asking:

```text
How do we sell more brain-training software?
```

It is asking:

```text
Can we prove a new category:
state-gated, transfer-oriented adaptive intelligence training
that users trust, complete, recommend and upgrade into?
```

## Current business scaling model hypothesis

The current IQ Mindware hypothesis can be written like this:

```text
If IQ Mindware clarifies Trident G IQ Pro as a state-gated adaptive intelligence programme,
activates existing buyers through Brevo,
publishes proof-led authority content,
uses mission tools and puzzles as low-friction feeders,
and builds IQ Coach as the stronger transfer-testing upgrade path,
then it can create a controlled scaling loop based on trust, activation, proof and upgrade demand.
```

The proposed strategic invariant is:

```text
state readiness
+ adaptive cognitive-control training
+ relational/problem-space reasoning
+ meta-epistemic prompts
+ delayed proof checks
+ claim-safe content
+ CRM activation
= transferable adaptive intelligence product pathway
```

This is still a hypothesis, not a settled claim. The attached strategy is careful about that: IQ Pro should be described as designed around far-transfer principles and evidence-generating, while avoiding claims of proven IQ increase, guaranteed g enhancement or fully validated far transfer. 

## The business ontology

The “ontology” of IQ Mindware would include these core objects:

| Object               | Meaning in the business                                                             |
| -------------------- | ----------------------------------------------------------------------------------- |
| **User / trainee**   | Someone moving through IQ Pro, IQ Coach, Zone, tools or puzzles                     |
| **State check**      | Readiness gate before deeper training or performance work                           |
| **Training session** | Capacity, n-back/control, reasoning or problem-space practice                       |
| **Proof fragment**   | Completion, activation, delayed re-check, user report or outcome snapshot           |
| **Content asset**    | Website page, Substack, video, proof FAQ, walkthrough or explainer                  |
| **Feeder asset**     | Puzzle, mission tool, Next-Test Planner, Decision Map, etc.                         |
| **CRM event**        | Brevo open, click, reactivation, onboarding or upgrade sequence                     |
| **CTA route**        | Buy IQ Pro, resume training, join IQ Coach, join Flow Zone, read proof              |
| **Surface signal**   | Search query, social response, objection, click pattern, support question           |
| **Action Intent**    | Bounded proposed move, such as sending a buyer email or updating a proof page       |
| **Clarify Intent**   | Information-gathering move when the market/niche signal is still opaque             |
| **Φ-Script**         | A reusable content, CRM, proof, partner or activation workflow that survives review |

That is where the Palantir analogy helps: the business should not be run as disconnected tools. It should be run as an integrated operational model.

## Four scaling levers as provisional hypotheses

The current Kastel implementation plan sensibly limits the first node to four levers: Content & Surface Intelligence, Conversion & CRM, Product Activation & Proof, and B2B / Partner Pilot Development. It explicitly frames the weekly kernel as a supervised priority engine producing 3–5 Action/Clarify Intents, not a broad autonomous agent stack. 

| Lever                                  | Hypothesis                                                                                     | Primary risk                                            | What would count as signal                                                                                    |
| -------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **1. Content & Surface Intelligence**  | Proof-led content can attract serious users and clarify the category.                          | Content volume without commercial learning.             | Website visits, Substack clicks, product-page visits, email captures, useful objections.                      |
| **2. Conversion & CRM**                | Existing buyers, subscribers and warm leads can be reactivated into usage, sales or waitlists. | Over-emailing or unclear CTAs.                          | Opens, clicks, purchases, resumed sessions, IQ Coach waitlist joins.                                          |
| **3. Product Activation & Proof**      | Better onboarding, completion guidance and proof pages can increase trust and retention.       | Claim overreach or weak evidence.                       | First-session completion, 20-session completion, delayed checks, support questions, proof-page engagement.    |
| **4. B2B / Partner Pilot Development** | Zone/readiness and proof-led cognitive performance can become legible to partners.             | Premature B2B effort before proof/positioning is clear. | Partner replies, pilot conversations, ranked niche shortlist, case-study permission, pilot outcome snapshots. |

The important point is that these are not just marketing channels. They are **learning loops**.

## Where the non-linear scaling might appear

The plausible B > 1 loops are:

| Scaling loop                | How it could become non-linear                                                                      |
| --------------------------- | --------------------------------------------------------------------------------------------------- |
| **Proof flywheel**          | More users complete → more proof fragments → clearer proof page → better conversion → more users.   |
| **Content compounding**     | Evergreen pages and Substack essays rank/share over time → more sign-ups without equivalent effort. |
| **CRM activation loop**     | Better segmentation → more resumed use/purchases → clearer user journeys → better future campaigns. |
| **Tool/puzzle feeder loop** | Puzzles/tools create social engagement → email capture → IQ Coach waitlist → product insight.       |
| **Upgrade loop**            | IQ Pro users understand limits/current pathway → IQ Coach becomes natural next step.                |
| **Partner trust loop**      | One pilot produces outcome snapshot → easier next partner conversation → repeatable pilot script.   |

The highest-value early loop is probably:

```text
IQ Pro clarity
→ buyer activation
→ completion/proof fragments
→ proof page
→ better content and CRM
→ IQ Coach waitlist
```

That is more immediately controllable than trying to launch Flow Zone, IQ Coach, puzzles, B2B and a full content machine all at once.

