# IQ Coach / Mission Arena

## Mindware-Level Training Component: Towers + Black Box

## 1. Purpose

The mindware-level component trains users to apply compact, reusable reasoning scripts inside bounded puzzle problem spaces, then reflect on whether the same epistemic stance can transfer to later tasks and real-world situations.

The target is not puzzle skill alone. The target is:

```text
relational WM support
→ puzzle problem-space navigation
→ mindware script use
→ meta-epistemic control
→ feedback-based updating
→ delayed and real-world reuse
```

In Trident-G terms:

```text
WM / relational training supports variable binding and relation tracking.
Mission Arena supplies structured problem spaces.
Mindware scripts provide reusable strategy templates.
Meta-epistemic prompts train the thinker’s control stance.
Reflection, transfer prompts and delayed checks test portability.
```

## 2. Evidence-consistent claim boundary

### Supported claim

```text
Mission Arena trains applied reasoning templates through structured puzzle missions,
meta-epistemic prompts, strategy notes, reflection and transfer prompts.

It is designed to test whether these templates survive changed wrappers,
delayed re-checks and later real-world use.
```

### Avoid

```text
Mission Arena raises IQ.
Puzzle training alone improves general intelligence.
Towers or Black Box automatically transfer to real-world decision-making.
This is already a proven far-transfer intervention.
```

### Best product wording

```text
Mission Arena is structured problem-space practice for adaptive intelligence:
users practise constraint reasoning, hidden-model testing, uncertainty calibration
and feedback-based updating through puzzle missions and transfer prompts.
```

The attached evidence review supports this conservative architecture: it treats strategies as trainable templates rather than theoretical operators, and emphasises that transfer depends on abstraction, varied practice, real-world cueing, feedback and delayed re-use.

# 3. Overall training architecture

Each mission follows the same sequence:

```text
1. Relational WM primer
2. Mission briefing
3. Meta-epistemic cue
4. Practice mode
5. Arena mode
6. Certainty / confidence check
7. Reflection prompt
8. Strategy note
9. Transfer prompt
10. Delayed re-check
```

## 3.1 Relational WM primer

Before the puzzle, the user completes a short relational WM exercise that primes the relevant relation family.

| Puzzle        | WM relation families                                                                     | Function                                                                   |
| ------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Towers**    | state maintenance, binding, ordinal chains, mutual exclusion, conjunction                | prepares the user to hold candidate values and constraint relations        |
| **Black Box** | conditional rules, counterfactual paths, equivalence, probabilistic updating, SR horizon | prepares the user to track hidden causes, possible paths and model updates |

This keeps the protocol integrated:

```text
WM relation
→ puzzle operator
→ meta-epistemic prompt
→ action
→ feedback
→ update
→ transfer cue
```

## Category C — Certainty calibration

### Skill

Tag the confidence level of a move, model or inference.

### Core prompt

```text
How certain am I, and why?
```

### Certainty ladder

| Level | Label             | Meaning                           |
| ----: | ----------------- | --------------------------------- |
|     0 | Unknown           | I do not yet know enough          |
|     1 | Possible          | This survives current evidence    |
|     2 | Plausible         | This fits more than one cue       |
|     3 | Probable          | This is the best current model    |
|     4 | Forced / Certain  | Alternatives have been ruled out  |
|     5 | Over-certain risk | I feel sure, but evidence is thin |

### Supporting prompts

```text
Is this forced, likely, possible or a guess?
What evidence supports this?
What alternative remains?
What would make me less certain?
Am I confusing fluency with proof?
```

### Towers use

```text
Is this placement forced, or only plausible?
```

### Black Box use

```text
How confident am I in this hidden layout before firing the next beam?
```

### Trains

```text
epistemic calibration
overconfidence control
uncertainty monitoring
belief updating
```

# 5. Puzzle-specific protocol: Towers

## 5.1 Training target

Towers trains **visible constraint-preserving reasoning**.

The user learns to:

```text
hold candidate states
bind values to cells
combine row, column and clue constraints
distinguish forced from plausible moves
make uncertainty-reducing placements
update the candidate map after each move
```

## 5.2 Primary mindware script: Constraint Check

```text
1. What must be true?
2. What cannot be true?
3. Which clue, row or column gives the strongest constraint?
4. What candidate can I safely remove?
5. Is the move forced, likely, possible or a guess?
6. What changed after the move?
```

## 5.3 Secondary script: Clue-to-Constraint Translation

```text
1. Read the clue as a relation, not just a number.
2. Convert the clue into an ordering constraint.
3. Mark the cells it affects.
4. Remove impossible heights.
5. Re-check row and column consequences.
```

## 5.4 Relational WM support

| WM training relation            | Towers application                                         |
| ------------------------------- | ---------------------------------------------------------- |
| **State n-back**                | maintain candidate values for cells                        |
| **Binding n-back**              | bind height ↔ cell ↔ row/column/clue                       |
| **Relation n-back**             | track change in candidate set after each clue or placement |
| **Transitive / ordinal chains** | infer visible height order constraints                     |
| **Conjunction**                 | combine row + column + clue constraints                    |
| **Mutual exclusion**            | one height per row and column                              |
| **SR horizon**                  | ask whether a placement preserves future solvability       |

## 5.5 Mission flow

### Mission briefing

```text
You are solving a visible constraint system.
Every move must preserve the row rules, column rules and edge clues.
Your task is not to guess quickly, but to narrow the space cleanly.
```

### Meta-cue before play

```text
What must remain true after every move?
```

### During-play prompt bank

Use sparingly, not all at once:

```text
Which clue matters most now?
What can be ruled out?
Is this move forced or only plausible?
Which constraints overlap in this cell?
What changed after that placement?
Could another height still work?
```

### Certainty check

Before a major placement:

```text
How certain are you?

[Possible] [Likely] [Forced] [Guess]
```

After feedback or completion:

```text
Was your certainty justified?

[Yes] [No] [Not sure]
```

### Reflection prompt

```text
Which clue, row or column reduced the most uncertainty?
```

### Strategy note

```text
Towers is a constraint-preservation problem.
Strong moves usually come from overlapping constraints:
a row rule, a column rule and a visibility clue together eliminate alternatives.
A move is certain only when every competing candidate violates at least one rule.
```

### Transfer prompt

```text
Where today do you need to make progress by preserving constraints rather than forcing an answer?
```

### Delayed re-check

Next day or later:

```text
Yesterday you used Constraint Check.
Can you remember the script?

What must be true?
What cannot be true?
What move reduces uncertainty?
What changed after feedback?
```

## 5.6 Towers proof events

```text
mission_started
wm_primer_completed
first_forced_move_identified
candidate_elimination_used
certainty_tag_submitted
incorrect_high_certainty_move
reflection_completed
strategy_note_viewed
transfer_prompt_completed
delayed_recheck_completed
```

## 5.7 Towers user-facing skill label

```text
Constraint Reasoning
```

Optional subtitle:

```text
Learn to preserve rules, eliminate impossibilities and identify forced moves.
```

# 6. Puzzle-specific protocol: Black Box

## 6.1 Training target

Black Box trains **hidden-structure inference from indirect evidence**.

The user learns to:

```text
hold rival hidden models
bind beam outcomes to possible layouts
simulate counterfactual beam paths
choose probes that reduce uncertainty
update confidence after evidence
distinguish possible, plausible and high-confidence models
```

## 6.2 Primary mindware script: Next Best Probe

```text
1. What are the rival hidden models?
2. What do I still not know?
3. Which beam would separate those models?
4. What result would change my mind?
5. Fire the beam.
6. Update the map.
```

## 6.3 Secondary script: Rival Models

```text
1. State the surprising observation.
2. Generate at least two possible hidden layouts.
3. Ask what each layout would predict.
4. Choose a discriminating beam.
5. Update confidence after feedback.
```

## 6.4 Relational WM support

| WM training relation                    | Black Box application                                          |
| --------------------------------------- | -------------------------------------------------------------- |
| **State n-back**                        | maintain current hidden-layout hypothesis                      |
| **Binding n-back**                      | bind beam entry ↔ path ↔ outcome ↔ possible ball positions     |
| **Relation n-back**                     | track how each probe changes the model                         |
| **Conditional rules**                   | if ball is in this relation to beam, then deflect/hit/reflect  |
| **Counterfactual relations**            | simulate what would happen under alternative layouts           |
| **Equivalence classes**                 | recognise when different layouts produce the same observations |
| **Probabilistic / confidence tracking** | tag models as possible, likely or high confidence              |
| **SR horizon**                          | choose probes that lead to useful future information           |

## 6.5 Mission flow

### Mission briefing

```text
You are investigating a hidden system.
You cannot see the balls directly.
You must infer their positions by choosing beams, reading outcomes and updating your model.
```

### Meta-cue before play

```text
Do not just collect beams.
Choose the beam that best tests your current model.
```

### During-play prompt bank

Use sparingly:

```text
What else could explain this beam?
What would I expect if my model were right?
Which beam would separate the rival models?
What result would prove this model wrong?
Could two layouts produce the same result?
How did this probe change my confidence?
```

### Certainty check

Before a beam:

```text
How confident are you in your current model?

[Low] [Medium] [High]
```

Before submitting a layout:

```text
Is this layout possible, likely or strongly supported?
```

After beam feedback:

```text
Did this probe raise, lower or leave unchanged your confidence?

[Raise] [Lower] [No change]
```

### Reflection prompt

```text
Which probe changed your model most?
```

### Strategy note

```text
Black Box is a hidden-model problem.
A strong move is not just another beam. A strong move is a probe that separates rival explanations.
High confidence is earned when your model predicts several beam outcomes and survives a discriminating test.
```

### Transfer prompt

```text
What is one real-world situation where you need to understand an invisible system by testing it indirectly?
```

### Delayed re-check

```text
Yesterday you used Next Best Probe.
Can you remember the script?

What are the rival models?
What do I still not know?
Which test would change my mind?
What changed after feedback?
```

# 8. Session-level implementation

## 8.1 Short Mission Arena session: 8–12 minutes

```text
1. Select puzzle: Towers or Black Box
2. 60–90 sec relational WM primer
3. Mission briefing
4. One meta-cue
5. Practice attempt
6. Arena attempt
7. Certainty check
8. Reflection prompt
9. Strategy note
10. Transfer prompt
```

## 8.2 IQ Coach integrated session: 15–20 minutes

```text
1. Zone / readiness check
2. Relational WM block
3. Mission Arena puzzle
4. Meta-epistemic prompt
5. Reflection
6. Transfer cue
7. Delayed re-check scheduled
```

## 8.3 Prompt dosage rule

Do not overload the user with prompts. Each mission should use:

```text
1 primary cue
1 certainty check
1 reflection prompt
1 transfer prompt
```

Additional prompts should appear only as optional “Need a hint?” or “Think deeper” buttons.

# 10. Why the two puzzles work well together

Towers and Black Box form an excellent first Mission Arena pair because they train complementary epistemic stances.

| Dimension        | Towers                               | Black Box                                    |
| ---------------- | ------------------------------------ | -------------------------------------------- |
| System type      | visible constraint system            | hidden causal system                         |
| Main error risk  | guessing before constraint proof     | collecting data without model discrimination |
| Core skill       | preserve constraints                 | test hidden models                           |
| Certainty type   | logical certainty                    | evidential confidence                        |
| Best prompt      | What must be true?                   | What test would change my mind?              |
| Transfer analogy | planning under constraints           | diagnosing invisible systems                 |
| WM support       | binding + exclusion + ordinal chains | conditional + counterfactual + SR horizon    |

Together, they support this central Mission Arena identity:

```text
Mission Arena trains two core adaptive-intelligence moves:

1. preserve constraints in a visible problem space
2. test hidden structure in an uncertain system
```

# 13. Final protocol summary

```text
The mindware-level component of Mission Arena trains compact reasoning scripts
inside bounded puzzle problem spaces.

Towers trains constraint-preserving reasoning:
What must remain true?
What is ruled out?
Is this move forced or merely plausible?

Black Box trains hidden-model reasoning:
What else could explain this?
What test would change my mind?
How should my confidence update?

Relational WM training supports the lower-level capacity to hold, bind, compare
and update the relevant variables and relations.

Meta-epistemic prompts convert successful puzzle operations into portable
control policies.

Reflection, transfer prompts and delayed re-checks test whether the policy
survives beyond the puzzle wrapper.
```

This gives you a coherent first mindware-level protocol: **Constraint Reasoning + Hidden-System Reasoning**, supported by **relational WM**, stabilised by **certainty calibration**, and tested through **reflection, transfer and delay**.
